# Table

Отдельный подпакет новой таблицы: `@sellgar/kit/table`. Подключён через `package.json#exports` и отдельный entrypoint Vite, по образцу `@sellgar/kit/icons`.

Реализован первый геометрический срез. Существующая таблица продолжает экспортироваться из `@sellgar/kit`; новая доступна через `@sellgar/kit/table` и используется в списке продуктов и на всех трёх уровнях списка склада Admin UI.

Слои разделены по ответственности:

- **Configurator** преобразует React-декларации колонок и render scopes в типизированную конфигурацию.
- **Core** содержит модель и чистые расчёты геометрии, ограничений, виртуализации и закрепления.
- **Runtime** владеет состоянием экземпляра, измерениями, событиями и публикацией snapshots.
- **View** отображает snapshots в React, применяет CSS Grid и токены `--numbers-X`.

```text
configurator/                 декларации и компиляция публичной схемы
core/column.ts                существующие модели деклараций
core/layout/                  состояние и чистая математика ширин/resize
core/geometry/                динамические суммы, поиск диапазонов, положение хедера
runtime/table-runtime.ts      snapshot и состояние экземпляра
runtime/measurements/          кеш измерений по rowId/columnId/version
runtime/browser/               DOM, observers, pointer capture, scroll owner
view/table/                    React owner, Context и композиция
view/table/surface/header/      отдельный слой единственного хедера
view/table/surface/body/        виртуальные строки и ячейки
```

В срез входят плоские строки, числовые fixed и автоматические колонки, min/max, направленный resize, два индикатора доступности, программный header, виртуализация обеих осей и динамические высоты с сохранением scroll anchor. Горизонтальная прокрутка принадлежит внешнему Table. Вложенные Table внутри Expand наследуют его viewport и выбранного вертикального владельца; отдельные Scrollbar не создаются. Необходимая ширина раскрытых уровней с учётом отступов передаётся вверх и входит в общую раскладку. При сворачивании требование освобождается. Внешний вертикальный scroll owner определяется по прокручиваемому предку либо странице; внутренний режим использует собственную панель для обеих осей. Единственный fixed-хедер остаётся DOM-потомком Table рядом со Scrollbar, ограничен горизонтальным viewport таблицы и движется вместе с ячейками. Table изолирует собственный stacking context с z-index:0; хедер имеет локальный z-index:1.

`data.getRowId` задаёт стабильный ключ при перезагрузке/перестановке данных. Без него сохраняется идентичность объектов; новый объект означает новую строку. Значение `rowHeight` — оценка виртуализации, min-height задаётся визуальным размером sm/md/lg.

Поверхность использует существующий kit `Scrollbar`: его графику, drag, auto-hide и floating horizontal track. Browser-адаптер работает с его фактическим scroll viewport; дополнительные полосы и отдельное состояние прокрутки не создаются.

Resize выключен по умолчанию. Для конкретной колонки его включает `resizable={true}`; последняя активная колонка игнорирует разрешение. Схема должна содержать хотя бы одну видимую auto-колонку.

Операция resize сохраняет начальные координату и ширину до отпускания. После выхода курсора за min/max ручка возобновляет движение при возвращении курсора к месту захвата на ручке. Последовательности с удержанием, разворотом и выходом за пределы покрыты runtime-тестами.

Сохранён визуальный контракт прежнего Table: header 22/28/32, строки минимум 40/54/64, фон и типографика темы, padding 12, горизонтальные разделители и центрирование содержимого. Expand поддерживается новым runtime: состояние по UUID, измеряемая высота раскрытого блока и scroll anchoring. Раскрытые владельцы остаются смонтированы за окном виртуализации для сохранения состояния вложенных таблиц; число таких DOM-узлов зависит от числа раскрытых строк. Обычные строки продолжают виртуализироваться. При сочетании click/doubleClick одиночный клик откладывается на 220 ms и отменяется двойным. Tree, selection, pinning и сортировка пока отклоняются явно. Непрерывный drag со сменой направления требует отдельной ручной проверки. Контентный предел берётся из `minWidth`; точный максимум всех виртуализированных ячеек не измеряется. Равные доли нескольких auto и переход O6 перенесены из эксперимента, их полный контракт остаётся открытым.

Контракт: [ТЗ](../../docs/table-layout-spec.md), [scope переноса](../../docs/table-migration-contract.md). Storybook не добавляется по уточнению пользователя.
