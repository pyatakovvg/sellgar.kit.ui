# Table

Отдельный подпакет новой таблицы: `@sellgar/kit/table`. Подключён через `package.json#exports` и отдельный entrypoint Vite, по образцу `@sellgar/kit/icons`.

Реализован первый геометрический срез. Существующая таблица продолжает экспортироваться из `@sellgar/kit`; новая доступна через `@sellgar/kit/table` и используется в списке продуктов и на всех трёх уровнях списка склада Admin UI.

Слои разделены по ответственности:

- **Configurator** преобразует React-декларации колонок и render scopes в типизированную конфигурацию.
- **Core** содержит модель и чистые расчёты геометрии, ограничений, виртуализации и закрепления.
- **Runtime** владеет состоянием экземпляра, измерениями, событиями и публикацией snapshots.
- **View** создаёт React-содержимое и состав виртуального окна. Browser `TablePresentation` синхронно применяет готовую геометрию в CSS Grid через `--numbers-X` до компенсации скролла.

```text
configurator/                 декларации и компиляция публичной схемы
core/column.ts                существующие модели деклараций
core/layout/                  состояние и чистая математика ширин/resize
core/pinning/                 отдельный бюджет и независимый resize pin
core/geometry/                общая геометрия pin/центра, проекция, оси и хедер
runtime/table-runtime.ts      snapshot и состояние экземпляра
runtime/columns/               настройки/resize колонок, pinWidth, fallback и геометрия
runtime/measurements/          кеш измерений по rowId/columnId/version
runtime/browser/               DOM, observers, pointer capture, scroll owner
view/table/                    React owner, Context и композиция
view/table/surface/header/      отдельный слой единственного хедера
view/table/surface/body/        виртуальные строки и ячейки
```

В срез входят плоские строки, числовые fixed и автоматические колонки, min/max, направленный resize, два индикатора доступности, программный header, виртуализация обеих осей и динамические высоты с сохранением scroll anchor. Горизонтальная прокрутка принадлежит внешнему Table. Вложенные Table внутри Expand наследуют его viewport и выбранного вертикального владельца; отдельные Scrollbar не создаются. Необходимая ширина раскрытых уровней с учётом отступов передаётся вверх и входит в общую раскладку. При сворачивании требование освобождается. Внешний вертикальный scroll owner определяется по прокручиваемому предку либо странице; внутренний режим использует собственную панель для обеих осей. До порога единственный хедер находится в нативном потоке поверхности. При программном закреплении его стабильный контейнер переносится в локальный portal host рядом со Scrollbar; slot сохраняет измеренную высоту. После обратного перехода контейнер возвращается в поток. Хедер остаётся DOM-потомком Table, ограничен её горизонтальным viewport и использует ту же геометрию колонок. React portal target не меняется, поэтому controls не перемонтируются. Table изолирует собственный stacking context с z-index:0; хедер имеет локальный z-index:1.

`data.getRowId` задаёт стабильный ключ при перезагрузке/перестановке данных. Без него сохраняется идентичность объектов; новый объект означает новую строку. Состав строк и tree children считывается заново при каждом рендере Table, включая повторную передачу того же изменённого массива. Реестр ID и runtime при этом сохраняются. Изменение обычного массива без рендера само не вызывает обновление Table. Значение `rowHeight` — оценка виртуализации, min-height задаётся визуальным размером sm/md/lg.

Поверхность использует существующий kit `Scrollbar`: его графику, drag, auto-hide и floating horizontal track. Browser-адаптер работает с его фактическим scroll viewport; дополнительные полосы и отдельное состояние прокрутки не создаются.

Resize выключен по умолчанию. Для конкретной колонки его включает `resizable={true}`; последняя активная колонка центра (вся схема без pin) игнорирует разрешение. Схема должна содержать хотя бы одну видимую auto-колонку.

Операция resize сохраняет начальные координату и ширину при движениях в неизменной геометрии. После выхода курсора за min/max ручка возобновляет движение при возвращении курсора к месту захвата на ручке. Нейтральные configure и обновления вложенных constraints не переносят эту опору. При изменении размеров контейнера или масштаба рабочая опора обновляется по текущей геометрии; cancel сохраняет отдельный снимок до захвата и пересчитывает его под актуальный контейнер. Последовательности с удержанием, разворотом и выходом за пределы покрыты runtime-тестами.

Сохранён визуальный контракт прежнего Table: header 22/28/32, строки минимум 40/54/64, фон и типографика темы, padding 12, горизонтальные разделители и центрирование содержимого. Expand поддерживается новым runtime: состояние по UUID, измеряемая высота раскрытого блока и scroll anchoring. Раскрытые владельцы остаются смонтированы за окном виртуализации для сохранения состояния вложенных таблиц; число таких DOM-узлов зависит от числа раскрытых строк. Обычные строки продолжают виртуализироваться. При сочетании click/doubleClick одиночный клик откладывается на 220 ms и отменяется двойным. Selection пока отклоняется явно; сортировка подключена как внешний запрос данных. Декларативные pinLeft/pinRight подключены; pin resize UI подключён для явно разрешённых колонок. Непрерывный drag со сменой направления требует отдельной ручной проверки. Явный `minWidth` отключает автоматическое измерение колонки. Без него пробный контентный минимум накапливается по смонтированным ячейкам; точный максимум всех виртуализированных ячеек не измеряется. Равные доли нескольких auto и переход O6 перенесены из эксперимента, их полный контракт остаётся открытым.

Контракт: [ТЗ](../../docs/table-layout-spec.md), [scope переноса](../../docs/table-migration-contract.md). Storybook не добавляется по уточнению пользователя.

## Математика pin

Внутренний `core/pinning` реализует `pinLayout`, `pinResizeBounds`, `resizePin`,
`initializePin` и `initializePins`.
На входе уже заданные ширины pin обеих сторон, их min/max и `{ width, reserve }`
в логических единицах numbers. Для чистого core резерв обязателен как входное
значение; default 50 разрешает ColumnRuntime перед вызовом core.

Общий предел равен width-reserve. При resize меняется только активный pin;
остальные сохраняют свои ширины, порядок и стороны. Результат содержит суммы
слева/справа, фактическую ширину центра и остаток бюджета. Некорректное исходное
состояние отклоняется исключением, без автоматического сжатия соседей или unpin.

Для одного перехода в pin `initializePin` принимает `PinCandidate`: id, side,
min/max и source. У auto source содержит текущую автоматическую base, у fixed —
исходную declaredWidth. Конечная ширина ограничивается собственными пределами и
остатком общего бюджета. Прежняя растянутая width/manual не используется и не
попадает в новый объект pin. Исходный объект обычного состояния остаётся у caller.
Недостаток места для min и повторный id отклоняются без изменения существующих pin.
`initializePins` добавляет набор атомарно. Желаемые ширины сначала ограничиваются
собственными min/max; если они не помещаются, часть сверх min уменьшается
пропорционально с общим коэффициентом. Существующие pin не меняются. При нехватке
места даже для суммы min весь переход отклоняется. Порядок кандидатов не влияет
на назначенные им ширины; выход сохраняет исходный порядок. Один `initializePin`
использует этот же расчёт. Два новых pin600 с min100 при бюджете950 получают475/475.

Модуль не зависит от обычной математики `core/layout`, React, DOM и CSS. Его фасад
не добавлен в публичный `@sellgar/kit/table`. Подключён к runtime; включение pin через
React-компонент использует эту математику через browser/runtime.

## Согласование pin и центра

Внутренний `core/geometry/table-layout.ts` содержит `tableLayout` и `projectColumns`.
Первый принимает обычное состояние всей видимой схемы, готовые pinWidth и
`{ width, reserve, surfaceWidth? }`. Состояние pin сопоставляется по id;
вычисления и порядок внутри групп опираются на порядок схемы. Выходной порядок —
левые pin, центр, правые pin, с исходными индексами для сопоставления с декларациями.

Центр рассчитывается прежним `automatic` на width-PL-PR. При заданной общей
surfaceWidth вызывается `sharedLayout` с обоими остатками: видимым и выделенным.
Pin исключены из обычного набора; их прежние обычные width/manual не участвуют.
LayoutAnchor относится только к центру. Обычная математика и pin не импортируют
друг друга; согласующий расчёт вызывает оба модуля, не дублируя их формулы.

Результат содержит обычный layout центра, итоговую длину/overflow и три смежные
области clipping. `overflow` считается относительно видимого viewport; у layout
центра он по-прежнему относится к его выделенной поверхности. `projectColumns`
переводит готовые позиции в viewport: центр движется со scroll, pin остаются
у своих краёв. Правые позиции считаются от группы pin, чтобы очень длинный центр
не стирал их ширины при вычитании больших чисел. Проекция не пересчитывает ширины.
Все значения остаются логическими numbers; Header/Body должны использовать одну
проекцию, не применяя горизонтальный scroll дважды.

Без pin ordinary/shared layout сохраняется. Некорректный бюджет и центр без auto
отклоняются, новые правила восстановления не назначаются. Возвращаемое переполнение
центра — математический результат; допустимость появления скролла при расширении
pin ещё требует решения O7. Runtime и React-компонент используют общий расчёт.

## Декларации размеров колонок

На Складе width/minWidth/maxWidth объявляются через `var(--numbers-X)`, например:

```tsx
<Column width={'var(--numbers-24)'} minWidth={'var(--numbers-24)'} pinLeft>
```

Числа также поддерживаются и означают логические единицы numbers, а не CSS px.
Конфигуратор разрешает numbers tokens до передачи числовых размеров в core:
целые 0–3000 и существующие дробные имена 0_1/0_2/0_3/0_5/0_6/1_5/1_6/1_7/2_2.
Неизвестный numbers token вызывает ошибку. Width с numbers token имеет режим
fixed; отсутствие width и прежние auto-строки сохраняют режим auto. Min/max
проверяются после разрешения tokens. Browser масштабирует DOM-координаты через
numbers-1 и выводит рассчитанные размеры через tokens; CSS-парсер в core не вводится.

## Pin в runtime

`ColumnRuntime` — владелец обычных настроек, отдельных pinWidth по id, anchors,
геометрии и resize. `TableRuntime` сохраняет владельца строк и измерений и объединяет
результаты в snapshot. `createGeometryColumns` сохраняет pinLeft/pinRight как metadata
pin, обычная математика её не интерпретирует.

Для схемы pin требуется хотя бы одна auto в центре. `ColumnRuntime` задаёт резерв
50 логических numbers по умолчанию. Необязательный `pinning: { reserve }` переопределяет
его, включая `0`; чистый core получает готовое числовое значение. До измерения ненулевого
видимого viewport инициализация отложена. Далее набор инициализируется один раз
из auto.base/fixed declaration; обычные manual/изменённая fixed width не становятся
pinWidth. Последующий scroll, данные и нейтральный configure не инициализируют pin заново.

Основное адаптивное поведение: если сохранённые ширины pin обеих сторон плюс
резерв не помещаются в видимый viewport, закрепление всего набора приостанавливается.
Это утверждённая политика компонента, а не временный обход ограничения.
Таблица использует обычные настройки и общий scroll owner. PinWidth остаются в snapshot
со статусом suspended; после возвращения места восстанавливается active. При недостатке
места для исходного набора min нет частичной инициализации. Начало fallback отменяет drag
с восстановлением его исходного checkpoint. Ошибки данных и невозможного заполнения
не маскируются: только PinBudgetError означает нехватку общего бюджета.

`beginResize(id, x)` работает в обычном контексте центра. `beginPinResize(id, x, edge)`
принимает координату относительно viewport и явную движущуюся границу left/right.
Pin не компенсируют друг друга, крайний pin может изменяться при resizable=true.
У центра остаётся собственное правило последней колонки. Rollback и рабочая опора
разделены; достижение min/max не переносит точку захвата. Scroll центра не влияет
на координату pin. Browser вызывает beginPinResize: у левого pin ручка справа, у правого слева.

Snapshot содержит порядок L/C/R, sourceIndex, region, offset, displayOffset, shift,
границы областей и pinning status/widths. Виртуальный набор объединяет все pin с окном
центра без дубликатов; строки/expanded и кеш измерений общие. Изменение ширин обновляет
version; scroll меняет только проекцию. Reconfigure сохраняет запросы по id, удаляет
исчезнувшие id и сбрасывает anchors при изменении схемы. Изменённая декларация размера
переинициализирует только соответствующий pin; при снятии флага pin через декларацию
его ширина не копируется поверх сохранённого обычного состояния.

Проверки этого этапа: 31 новый тест публичных методов TableRuntime, включая 800 seeded
переходов resize/scroll/fallback/restore; полный набор Table254. Результаты этого runtime-этапа не подменяют проверку отображения; подключение view описано ниже.

Проверки из корня пакета:

```bash
../../node_modules/.bin/tsc -p tsconfig.json --noEmit --incremental false
../../node_modules/.bin/vitest run --config vitest.table.config.ts
../../node_modules/.bin/vite build
```

## Дерево и перенос оставшихся consumers

`tree={{ isUse: true, accessor: (row) => row.children }}` строит preorder с глобально уникальными
идентификаторами, `node.depth` и `node.parentNodeId`. Некорректные children и циклы
отклоняются. По умолчанию ветви свёрнуты; `defaultExpanded` раскрывает их изначально.
`accessor` получает тип строки из `data.nodes` и возвращает `readonly T[]`, `null` или
`undefined` (лист). Функция может читать вложенное поле или отфильтровать детей;
она вызывается для каждого узла при обходе дерева и должна быть без побочных эффектов.
`Cell.render` получает `TreeTrigger` для явной колонки кнопок. Саму глубину отображает
consumer; кнопка не вызывает primary row action.

Core строит дерево и рассчитывает видимость. Runtime хранит disclosure по rowId,
сохраняет состояние вложенных ветвей и измеренные высоты скрытых потомков,
виртуализирует только видимые узлы. Browser применяет scroll correction при сворачивании
ветви с текущей опорной строкой. Resize и раскрытие деталей строки независимы от дерева.

Admin consumers: продукты, склад, бренды, единицы, свойства, магазины, шаблоны,
категории и учётные записи в карточке склада используют новый entrypoint.
Проверка реальной страницы категорий блокируется HTTP 404 `/v2/categories`;
это существующий backend-контракт, а не ошибка таблицы.

## Исправления после аудита логики

- Ошибка геометрии не размонтирует раскрытых потомков: их constraints остаются
  действующими. Содержимое скрыто и inert до восстановления; Header возвращается
  в текущий slot после снятия ошибки. Новая схема получает собственную безопасную
  геометрию даже при ошибке заполнения.
- Направленный resize применяется к снимку начала захвата. Компенсация меняет
  существующие правые auto на равную дельту с ограничениями; нулевая дельта и
  нейтральный reflow сохраняют индивидуальные ширины. Первоначальные равные доли
  сохранены; открытые решения O2–O6 этим не закрываются.
- Вложенная таблица различает `viewport.available` (доступную ширину viewport)
  и `viewport.container` (выделенную общую поверхность). Ручная потребность
  рассчитывается относительно reference и передаётся вверх вместе с рамками и
  отступами. Заполнение общей поверхности не увеличивает эту потребность повторно.
- Опора прокрутки по rowId и внутреннему смещению применяется при configure,
  измерениях и раскрытии. При удалении опоры выбирается следующий сохранившийся
  элемент прежнего порядка, затем предыдущий; при сворачивании дерева — предок.
  Для таблицы ниже viewport configure не прокручивает внешний контейнер.
- Browser отслеживает перемещение поверхностей одним общим frame loop: сначала
  читает позиции, затем обновляет только сдвинувшиеся таблицы. Fixed probe измеряет
  начало координат локального fixed containing block. Scroll/clipping учитывают
  масштаб предков; Header остаётся внутри Table.
- `Actions` отображаются через системный Popover с нативными disabled-кнопками.
  Renderer получает id из React key декларации; для статичных деклараций без key
  сохраняется позиционная идентичность, как у Column. Для динамического порядка
  нужны явные key. Повторяющиеся key отклоняются.
- ResizeHandle поддерживает ArrowLeft/ArrowRight (1 логическая единица) и Shift
  (10), сохраняя runtime permissions/min/max. Индикаторы используют
  `--icon-base-secondary` и `--icon-status-success`. ExpandTrigger имеет локальный
  visual reset и focus-visible.

## Исправления повторного аудита

- Actual-ширина auto не опускается ниже её base после компенсации fixed; возврат
  ручной auto к базе сохраняет согласованную геометрию. Нулевая горизонтальная
  дельта сохраняет исходный manual, включая запрос, временно скрытый ростом базы.
- Browser различает логические единицы таблицы, CSS-пиксели scroll owner и экранные
  координаты DOM. Ширины, высоты и позиции View продолжают использовать
  `--numbers-X` через `serializer/numbers.ts`; эта функция только записывает число
  как `var(--numbers-X)` либо `calc(var(--numbers-1) * число)`. Измерения контента
  и рамок приводятся к общей системе, компенсация прокрутки — к единицам owner.
- При изменении rowHeight/minRowHeight существующие и невидимые строки получают
  актуальную оценку/минимум; сырые измерения сохраняются. Произвольный Empty
  измеряется отдельно и входит в высоту поверхности.
- Row guard учитывает ARIA-контролы и contenteditable, включая plaintext-only.
  Отложенный click обращается к актуальным данным и handlers. Строка с primary
  click доступна через Tab и активируется Enter/Space нативным click; клавиши
  вложенных controls не активируют строку.
- Actions удаляются вместе с локальным open state при исчезновении деклараций.
  Их Popover.Trigger явно получает button semantics, keyboard lifecycle остаётся
  системным.

## Отображение pin

`Column.pinLeft` / `Column.pinRight` включают закрепление. Резерв центра по умолчанию —
50 логических numbers. Consumer переопределяет его через
`layout={{ pinning: { reserve: 80 } }}`, включая допустимый `0`. Отсутствующий
`pinning`, пустой объект и `reserve: undefined` используют default. Auto в центре обязательна.
Pin с `resizable=true` используют отдельную операцию через browser-адаптер.

Flow HeadCell и Cell используют нативное горизонтальное `position: sticky` с
готовым `pinInset` из core. Pin не получают обратный scroll-transform от React.
Центр проходит под непрозрачными pin; единственный Scrollbar обрезает поверхность.
Вертикальный sticky-механизм Header сохранён: при выносе в локальный fixed portal
pin стоят на постоянных viewport-координатах, scroll-transform получают только
центральные HeadCell. Header не клонируется. Фокусируемые controls центра при
попадании за pin раскрываются минимальной прокруткой общего scroll owner.

На реальном `/store` закреплены статус и «Товар» слева, «Витрина» справа,
reserve50 используется по умолчанию. Во встроенном браузере проверены оба края scroll,
смена направления, flow/portal Header и раскрытые три уровня с общей полосой.

### Горизонтальное движение закреплённого Header

Browser `HeaderScroll` связывает transform центральных ячеек портального Header
с `ScrollTimeline` фактического горизонтального owner. Ширины по-прежнему приходят
из core/runtime. Реальный диапазон scroll переводится в numbers, keyframes используют
`--numbers-1`; горизонтальный transform не проходит через React snapshots. Pin
остаются на постоянных координатах, вертикальный translate Header не меняется.
На изменении диапазона keyframes обновляются, на scroll анимации не перезапускаются.
Без native API browser применяет прямой transform до рендера React. При возврате
в flow, смене owner и удалении виртуальных HeadCell эффекты освобождаются.

## Критичная синхронизация DOM

`TableBrowser` подписан непосредственно на runtime. `TablePresentation` применяет
ширины поверхности, Header/Line, позиции и высоты Row/Body, pinInset/displayOffset,
вертикальные координаты и flow/portal placement Header до возврата команды runtime.
React не записывает эти же свойства. После commit адаптер согласует новые элементы
виртуального окна. Вложенные Table обрабатываются собственными адаптерами.

Новая высота Body применяется до native scroll correction: браузер уже видит новый
scroll range и не обрезает компенсацию старой границей. При смене версии геометрии
адаптер повторно измеряет зарегистрированные элементы, даже если ResizeObserver
не прислал новое событие. Очередь сохраняет проверку версии в runtime.

Горизонтальные pin и flow Header движутся нативно; центр portal Header связан с
реальным scroll owner через ScrollTimeline. В системном Scrollbar thumb использует
такую же native timeline; размер и fallback transform применяются DOM-владельцем.
React сохраняет содержимое, controls, доступность и видимость track. Вертикальный
portal Header обновляется напрямую адаптером по native scroll events; это исключает
ожидание React commit, но не обещает compositor-синхронизацию во всех браузерах.

## Ресайз pin в интерфейсе

Ручка стоит на движущейся границе: справа у левого pin, слева у правого.
`resizeEdge` и физические left/right индикаторы вычисляет ColumnRuntime по
resizeBounds. Browser выбирает beginResize либо beginPinResize; keyboard вызывает
ту же операцию. Pin pointer X относится к видимому viewport, без scrollLeft центра.
Общий pointer capture остаётся у стабильного root; Escape/cancel и rebase сохраняются.

Середина ручки шириной numbers10 совпадает с геометрической границей. Разделитель
numbers3 симметричен относительно этой же оси; Header/Body рисуют его только
на внутренних краях pin-групп. Контент ячеек обрезается отдельно. Локальный порядок
HeadCell позволяет захватывать обе половины ручек между соседними pin.

## Сортировка, lastRowTrigger и совместимые контексты

- Column.sort использует directionDefault, onToggle(direction), onReset(). По умолчанию
  запрос не отправляется; click/Enter/Space переключают asc/desc. Активна одна колонка.
  Данные сортирует потребитель и передаёт обновлённые nodes.
- lastRowTrigger вызывает onLastRowVisible(row) при достижении последней видимой data
  строки. rootMargin — CSS px, threshold — от0 до1. По умолчанию запас равен высоте
  наблюдаемой ячейки. root — фактический scroll owner, Window соответствует root=null.
  Дедупликация по rowId сохраняется через виртуальные remounts; смена последней строки
  разрешает следующий вызов.
- Совместимые hooks импортируются вместе с новой Table:
  import { Table, useCellData, useRowExpanded } from '@sellgar/kit/table'.
  useCellData<T>() возвращает { id, data, deps }, где deps — глубина дерева.
  useRowExpanded() возвращает { expanded, onToggle }.
- Поддерживаются render scopes и compound aliases Table.Column/Head/Cell/Empty/Expand/ExpandTrigger.
- Сохранены новые defaults: size=md, virtualization=true, явная колонка дерева.
  Выбор строк/его controller не реализованы. Контентный минимум подключён как пробный механизм, описанный ниже.

## Пробный минимум по содержимому

Если `Column.minWidth` задан (включая 0 и numbers token), колонка не регистрируется
для измерения ширины контента. Явный минимум остаётся единственным таким ограничением.
Без `minWidth` browser измеряет скрытые inert-копии смонтированных заголовков и
Cell content с сохранением шрифта и padding; учитывает sort/menu, исключает resize.
React renderers повторно не исполняются, невидимые строки не монтируются.

Измеряется max-content в logical numbers через текущий scale. Runtime накапливает
максимум увиденного в текущем наборе данных и ограничивает его опорной шириной:
для fixed это declared width, для auto — первоначальная base при положительном viewport.
Явные maxWidth, заполнение контейнера, обычная компенсация и pin-бюджет сохраняются.
Измерения не выполняются во время drag; новые ограничения применяются после
finish/cancel. Индикаторы и обе операции resize получают общий эффективный floor.

Смена состава/порядка/идентичности данных и явные changedRows сбрасывают накопления;
обычный unmount виртуальной ячейки их сохраняет. Source mutations, load изображений
и завершение загрузки шрифтов запрашивают повторное измерение видимых источников.
В пределах одного набора данных максимум не уменьшается сам. O2/O4 остаются
пробной политикой: это не обещание точного размера всех строк, а custom CSS с
процентами, container queries или зависимостью от ancestry требует отдельной проверки.

## Сброс ширины двойным кликом

Двойной клик по ResizeHandle сбрасывает только выбранную колонку. Fixed возвращается
к объявленному width через направленную компенсацию; у auto удаляется manual,
и ширина рассчитывается для текущего контейнера и остальных колонок. Pin возвращается
к принятой ширине своей инициализации, а не к неограниченной исходной декларации.
Текущие min/max, контентный предел, заполнение поверхности и pin-бюджет сохраняются.
Остальные ручные настройки не сбрасываются, сортировка не вызывается. При активном
перетаскивании и для запрещённых/последних обычных колонок команда не выполняется.
