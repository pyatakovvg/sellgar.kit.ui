# Состояние колонок runtime

- ColumnSort отдельно хранит активный запрос сортировки и актуальные callbacks по id.
  Он не меняет ColumnRuntime, data.nodes, pin/layout или их anchors. Публикация состояния
  предшествует внешним callbacks; default не вызывает onToggle. При исчезновении активной
  sortable-колонки вызывается её сохранённый onReset, независимо от её удаления из схемы.

- `ColumnRuntime` владеет обычными настройками, anchors, отдельными pinWidth по id,
  геометрией колонок и текущим resize. TableRuntime владеет строками/измерениями
  и публикует совместный snapshot; браузер продолжает владеть координатами DOM.
- Все входы — логические numbers. Pin-бюджет берётся только из viewport.width,
  широкая поверхность и nested demand не увеличивают его.
- Content minimum включается через measureContent=true при подготовке геометрических
  auto-колонок без числового width в createGeometryColumns, в том числе при явном minWidth, включая 0.
  Fixed-колонки с явным width не измеряются по содержимому. Если minWidth отсутствует, floor равен width после применения maxWidth; явный minWidth, включая 0, заменяет этот floor.
  Эффективный floor — максимум объявленного minWidth и измеренного содержимого,
  ограниченного явным maxWidth. Начальная auto base не ограничивает floor.
  Epoch меняется при смене схемы/данных; устаревшие результаты игнорируются.
  Во время resize новые floor откладываются до finish/cancel. Unmount виртуальной
  ячейки не сбрасывает накопления. Для auto с явным minWidth отдельный resizeFloor
  разрешает сужение ниже контентного floor; manual сохраняет пользовательский запрос
  при пересчёте и новых измерениях. Обычная геометрия и pin используют resizeFloor
  как минимум resize. Reset снимает ручной запрос и возвращает автоматический расчёт.
- Configure добавляет постоянную внутреннюю auto-компенсацию после пользовательских колонок.
  При размещении pin она завершает центр. Компенсатор без контента, floor=0,
  measureContent=false и resizable=false; при нулевой ширине не попадает в render projection/grid.
  Automatic сначала распределяет пространство между пользовательскими auto; result заполняет
  остаток компенсатором. Auto можно вручную уменьшить до floor; изменённые bases сохраняются
  anchor, чтобы нейтральный configure не отменял сужение. Reset auto освобождает anchor.
- Последняя пользовательская колонка не теряет разрешение resize. Математические
  индикаторы отражают min/max, видимую правую границу добавляет DOM presentation
  без React-публикаций на scroll. Browser ограничивает pointer/keyboard и итог завершения.
- Инициализация и resize используют готовую математику core. При изменении scroll
  обновляется проекция, а сохранённые ширины не инициализируются заново.
- ColumnRuntime задаёт reserve=50 логических numbers по умолчанию; options.pinning.reserve
  переопределяет его, включая 0. Core получает уже разрешённое числовое значение.
  Компенсатор обеспечивает заполнение центра. Основная адаптивная политика: нехватка бюджета
  PL+PR+reserve > viewport.width приостанавливает весь набор pin. PinWidth и настройки
  сохраняются; при возвращении достаточного места закрепление восстанавливается.
  Это штатный контракт, не временное решение и не частичный автоматический unpin.
- Pin операция получает сторону движущейся границы явно от caller. Сторона
  ручки React-компонента этим не выбирается. Scroll центра не входит в pin pointer X.
- Configure сохраняет ручные ширины, pin и измеренный content minimum оставшихся ID при неизменных ограничениях. Удалённые ID исключаются из declarations, pin, initialPinWidths и contentWidths; возвращение инициализирует колонку из декларации.
- Schema и разрешения сопоставляются по id. Изменение контекста отменяет drag;
  обычные обновления данных и одинаковые constraints не переносят точку захвата.
- Cancel хранит исходный checkpoint отдельно от рабочей опоры; выход за min/max
  и разворот не переносят её. Изменение геометрии rebase делает только рабочей опоре.
- resetColumnWidth снимает manual у auto и заново получает автоматическую раскладку.
  Fixed возвращается к declared width через обычный directed resize. Pin возвращается
  к ширине своей инициализации через независимую pin-операцию. Текущие min/max,
  заполнение и общий бюджет ограничивают сброс; остальные manual не очищаются.
  Во время активного drag сброс не выполняется; обычная последняя колонка запрещена.
- Public Table поддерживает pin и явный resizable. Пользовательский pin/unpin
  пока не подключён. Новые public entrypoints и stories не создаются.
- PinBudgetError включает только нехватку бюджета. Ошибки данных и невозможного
  заполнения центра не маскируются fallback. Невалидный запрос во время pin drag
  отклоняется с сохранением последней допустимой геометрии.
- Snapshot pin resizeBounds содержит собственные min/max, общий бюджет и ограничение
  заполнения общей поверхности конечными maxWidth центра. Тот же интервал применяется к drag. Физические
  resizeEdge задаёт правую границу для левого pin и левую для правого; физические
  left/right индикаторы отражают min/max этой границы. Дополнительная политика overflow центра не назначена.
