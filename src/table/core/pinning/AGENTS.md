# Pinning core

- Отдельная чистая математика пинов. Не зависит от `core/layout`, runtime, React, DOM или CSS.
- Фасад `index.ts` приватен для Table; не добавлять его в публичный entrypoint пакета без отдельной задачи.
- Входные width/minWidth/maxWidth, viewport.width и reserve — логические числа шкалы numbers. Значение резерва задаёт caller; чистый core не назначает default. Default 50 принадлежит ColumnRuntime.
- `pinLayout` проверяет уже заданные ширины и общий бюджет обеих сторон. Возвращает суммы слева/справа, ширину центра и остаток.
- `pinResizeBounds` рассчитывает min/max активного пина; `resizePin` меняет только его ширину, сохраняя порядок, стороны и остальные пины.
- Некорректное исходное состояние отклоняется исключением. Нехватка общего бюджета имеет отдельный PinBudgetError (подтип RangeError); runtime не распознаёт ошибки по тексту. Функции бюджета/resize принимают готовые ширины; политика временного отключения/восстановления принадлежит runtime.
- `initializePin` выполняет один переход обычной колонки в pin: auto берёт source.base, fixed — source.declaredWidth, затем применяются min/max и свободный общий бюджет. Новый объект содержит только данные pin; обычное состояние остаётся у caller и не мутируется.
- Вход `PinCandidate` не принимает текущую растянутую ширину или manual как источник. Source — отдельный discriminated union; лишние поля исходного объекта в pin не копируются.
- `initializePins` атомарно добавляет набор новых pin. Сначала проверяет существующее состояние и возможность разместить все min, затем ограничивает желаемые ширины собственными min/max. При нехватке бюджета часть сверх min уменьшается с одним общим коэффициентом; существующие pin не меняются.
- `initializePin` делегирует этому же расчёту набор из одного кандидата. Промежуточное min-состояние не публикуется; источники auto/fixed и бюджет не имеют второй независимой реализации.
- Существующий id отклоняется: повторный вызов не должен сбрасывать уже изменённую pinWidth. Недостаток места даже для min отклоняется без сжатия остальных.
- Если желаемый набор помещается, ширины сохраняются без заполнения остатка. Если не помещается сумма min, весь переход отклоняется. Нулевые/locked pin и пустой набор допустимы по тем же ограничениям.
- Для вычислений суммы упорядочиваются по id; выход сохраняет исходный порядок existing и кандидатов. Перестановка не меняет назначенные ширины по id и не задаёт приоритет первой колонке.
- Коэффициент рассчитывается с нормализацией избытков, чтобы сумма больших конечных желаемых ширин не переполняла Number. При underflow коэффициента применяется эквивалентная доля бюджета.
- Пропорциональное распределение действует только при совместной инициализации новых pin. Последующий resize остаётся независимым и не запускает повторную инициализацию.
- Отрицательный конечный target допустим как запрос сужения: он ограничивается min. NaN/Infinity недопустимы. Отсутствие maxWidth и +Infinity означают отсутствие собственного максимума, но общий бюджет действует всегда.
- При сравнении суммы с бюджетом учитывается только погрешность Number.EPSILON с масштабом и числом слагаемых; дробные ширины не округляются. Нулевая/пограничная операция сохраняет достижимость исходной ширины.
- Пользователь последовательно разрешил бюджет/resize, single-pin инициализацию из base/объявленной ширины, атомарную инициализацию набора и подключение runtime. Permissions, checkpoints, отдельная pointer-ось pin и fallback теперь принадлежат runtime/columns. Положение ручек и wiring browser/UI подключены вне core через resizeEdge.
