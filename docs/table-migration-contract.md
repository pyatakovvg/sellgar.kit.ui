# Перенос геометрического среза Table

- Источник: поручение перенести проверенный стенд в архитектуру Table, затем подключить его в модуле продуктов и запустить админку с необходимыми сервисами.
- Ветка: `master`. Репозитории: UI kit и Admin UI. Существующие изменения конфигуратора сохраняются.
- Scope: чистое ядро раскладки и геометрии; runtime каждого экземпляра; браузерный адаптер; React view; подключение существующего конфигуратора; замена таблицы только на экране продуктов. Storybook отменён пользователем.
- Миграция остальных consumers, старая таблица, tree, selection, pinning и expanded rows в этот срез не входят. Неподдерживаемые опции отклоняются явно.
- Правила: сумма ширин не меньше контейнера; у последней видимой колонки всей схемы нет resize-ручки; два индикатора показывают фактические ограничения; единственный хедер находится вне прокручиваемого слоя.
- Состояние: runtime создаётся для каждого Table; строки идентифицируются через `data.getRowId` либо по идентичности объектов; measurements и ручные ширины не принадлежат React view.
- Сохранённые экспериментальные решения: равные исходные доли auto с min/max; сохранение направленной раскладки при resize контейнера. Это перенесённый проверяемый срез, не закрытие всех O2–O6.
- Контентный предел в первом срезе задаётся `minWidth`. Точное измерение максимальной потребности всех виртуализированных ячеек не реализовано.
- Приёмка: типы и сборка отдельного entrypoint; тесты ядра и последовательностей runtime; экран продуктов получает реальные данные, открывает товар по row click; проверяются resize, виртуализация, измеряемые высоты и закрепление во встроенном браузере.
- Runtime: переиспользовать PostgreSQL/RabbitMQ; запустить identity, product, admin gateway и Admin UI. Дополнительные сервисы запускать только при фактической зависимости экрана.
- Commit/push и изменение gitlinks не входят в поручение.

- TypeScript UI kit и Admin UI: успешно. Сборка kit с отдельным entrypoint Table: успешно. Vitest: 3 файла, 40 тестов успешно, включая runtime на 10 000 строк.
- Во встроенном браузере проверены 13 реальных продуктов: заполнение контейнера, resize первой колонки, отсутствие ручки последней колонки, направление индикаторов и открытие редактора по клику. При уходе с экрана portal хедера удаляется. После свежей загрузки ошибок консоли нет.
- Большой набор строк и быстрый scroll закреплённого хедера в интегрированном экране не проверены: текущая выдача содержит 13 товаров. Проверка большого набора в runtime не заменяет эту проверку view.

- Admin UI, admin gateway, identity и product запущены; PostgreSQL и RabbitMQ переиспользованы. Проверенный сценарий списка и открытия редактора не потребовал дополнительных сервисов. Данные не изменялись.

## Сохранение точки захвата при resize

- Источник: «решай и тестируй на том же кейсе». Scope: операция resize в runtime, её приватный тип и регрессионные тесты. Механика закрепления хедера, browser-адаптер и математика распределения колонок не меняются.
- Сценарий: один захват → расширение вправо → движение влево за минимальную ширину → возврат вправо без отпускания. Ручка возобновляет движение после возвращения курсора к исходной точке захвата на ручке, а не сразу после разворота курсора.
- Red evidence: при начальной ширине 500 и захвате на X=486 перемещения 686 → 286 → 306 дают ширины 700 → 500 → 520. На последнем шаге точка захвата ручки находится на X=506, хотя курсор ещё на X=306.
- Решение: начальные координата и ширина неизменны до завершения операции; min/max ограничивают только текущий результат. Та же гарантия применяется к выходу за верхний предел, разным местам захвата и нормализованным координатам после горизонтальной прокрутки.
- В runtime сохранены `readonly startX/startWidth`; операция не переносит опору при достижении предела. Регрессии находятся в `src/table/runtime/__test__/table-resize.test.ts`.
- Red/green: все 8 новых случаев падали до исправления; после исправления проходят все 48 тестов подпакета. В исходной последовательности 686 → 286 → 306 → 466 → 486 → 506 ширины равны 700 → 500 → 500 → 500 → 500 → 520, операция остаётся активной до одного финального `finishResize`.
- TypeScript kit, Vite build, форматирование изменённых исходников и `git diff --check`: успешно. Browser smoke `/products`: расширение первой колонки с 276.5 до 376.5 px даёт собственный X overflow таблицы; возврат за минимум останавливается на 276.5 px при общей ширине 553 px. Header остаётся `position: fixed`; его механизм не изменён.
- Ограничение evidence: непрерывный физический жест со сменой направления недоступен через текущий browser-инструмент. Тот же порядок перемещений без отпускания проверен сохранённым тестом реального runtime; отдельные завершённые drag в админке служат smoke-проверкой интеграции.

## Декомпозиция ручки захвата

- Новые файлы размещены в `src/table/view/table/surface/header/head-cell/resize-handle`, стили ручки перенесены из HeadCell. Фасады и локальные AGENTS описывают границы. Component tests и stories не добавляются.
- Проверка: TypeScript, 48 существующих тестов, Prettier изменённых исходников и `git diff --check` прошли. В `/products` ручка сохранила размер 28×27 px, два индикатора, label и ограничение последней колонки. Drag +100 px изменил ширину с 276.5 до 376.5 px; левый индикатор переключился из недоступного в доступный; обратный drag восстановил ширину.
- ESLint вызван для изменённых TS/TSX, но конфигурация исключила все четыре файла (`no matching configuration supplied`); это не успешная lint-проверка. Production build не запускался для локальной декомпозиции без изменения public API.

## Курсор во время захвата

- Scope: Header TSX и его CSS Module. Pointer capture, расчёты resize, положение хедера и пользовательское оформление ResizeHandle не меняются.
- Red evidence `/products`: у кнопки cursor `col-resize`, у захватывающего указатель Header — `auto`. Во время одного реального drag собраны 22 измерения с активным `dragging`; во всех cursor захваченного элемента оставался `auto`.
- Исправление: Header получает существующий флаг snapshot.dragging; CSS задаёт `col-resize` на всём сроке захвата. После finish/cancel runtime сбрасывает флаг и временный cursor перестаёт действовать. Дополнительного состояния и глобальных стилей нет.
- Green evidence: во время реального drag 21 измерение активного захвата показало Header cursor `col-resize`; после отпускания dragging=false и cursor `auto`. TypeScript, 48 существующих тестов, Prettier двух изменённых файлов и `git diff --check` прошли. Скриншот не подтверждает форму системного курсора; проверка выполнена по computed style элемента pointer capture во время жеста.

## Локальный слой хедера

- Источник: «надо исправить этот баг» — вложенные хедеры перекрывают панели и чужой контент. Scope: Header view и изоляция слоя Surface. Программная геометрия fixed-хедера, core/runtime, resize и публичный API сохраняются.
- Причина: createPortal в document.body обходит stacking contexts владельца. Ограничение видимой области через координаты и clip-path не восстанавливает порядок слоёв.
- Решение: единственный Header остаётся дочерним узлом Surface, рядом со Scrollbar, вне собственного scroll viewport; Surface изолирует stacking context. Header сохраняет fixed-позиционирование, pointer capture, clipping и измерения. Глобальный portal и его lifecycle удаляются.
- Дополнение пользователя: хедер на один уровень выше таблицы. Локальные индексы Surface=0, Header=1 вместо глобального Header=20.
- Browser-проверка выявила обратную связь размеров во вложении в старый Grid с minmax(max-content,auto): рассчитанная ширина содержимого новой таблицы увеличивала intrinsic-ширину родителя, а та повторно увеличивала auto-колонку. Surface получает contain:inline-size, чтобы ширину контейнера задавал родитель, а не измеренная ширина содержимого. Layout/paint containment не используется: fixed-хедер сохраняет систему координат viewport.
- Приёмка: на /store два вложенных хедера не перекрывают inventory drawer, остаются в границах таблиц при X/Y scroll и работают после закрытия панели; на /products сохраняются resize, X scroll, закрепление и скруглённый контур. Проверки: TypeScript kit/Admin, существующие тесты core/runtime, форматирование и diff check. Stories и component tests не добавляются.

## Полное применение в модуле склада

- Источник: пользователь уточнил необходимость применения новой таблицы ко всему модулю, отвергнув частичную пробу. В scope входят все три уровня списка /store, сохранение single click карточки, double click раскрытия, nested inventory action и устранение воспроизводимого застревания resize. - Приёмка: все imports Table в modules/store ведут в @sellgar/kit/table; реальные товары/варианты/записи открываются и сворачиваются, корректно сдвигают следующие строки, двойной клик не открывает карточку; одиночный открывает карточку; inventory drawer получает правильную запись. Declared minWidth=140 у уточнений сохраняет поле в узкой таблице и создаёт собственный X overflow; глобальный intrinsic content minimum остаётся отдельным ограничением текущего среза.

## Явное разрешение resize каждой колонки

- Источник: пользователь потребовал resize=false по умолчанию, индивидуальное включение и безусловный запрет для последней колонки; отсутствие auto является ошибкой конфигурации.
- Scope: Column.resizable, компиляция declaration → geometry, runtime start/snapshot, защита core и регрессионные тесты. Последняя определяется после visible/order, по всей активной схеме. Математика ширин, header и expansion не меняются.
- На складе явных разрешений нет — ручки исчезают на всех уровнях. В продуктах resize ранее использованной первой колонки включается явно. Запрет схемы без видимой auto уже есть в компиляторе; его сохраняем и проверяем также на нормализованной геометрии.
- Приёмка: omitted/false не дают ручку и не позволяют beginResize; true работает на внутренней колонке; true последней игнорируется. Скрытая auto не делает схему из fixed допустимой. Проверки compiler/core/runtime, TypeScript kit/Admin, build публичного entrypoint и browser smoke склада/продуктов. Commit/push не выполнять.

- Red evidence: новый тест default/false и тест core с двумя fixed и overflow падали до правки. После правки проходят все 65 tests. Компилятор сохраняет resizable, factory переносит флаг в geometry, runtime запрещает захват disabled/last и снимает активный drag при отзыве разрешения. Изменение разрешений сохраняет завершённые ручные ширины.
- Browser smoke: после свежей загрузки /store раскрыты товар и оба варианта; четыре экземпляра Table содержат ноль resize-ручек, expansion работает. На /products единственная явно разрешённая description имеет одну ручку, drag +100 меняет её ширину 276.5→376.5, brand остаётся 276.5.
- TypeScript kit/Admin, 65 tests, форматирование и Vite build с декларациями прошли. ESLint исключил семь целевых TS/TSX (no matching configuration supplied); это ограничение проверки, а не успешный lint. ТЗ и README обновлены по требованию пользователя.
